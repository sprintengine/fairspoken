# Fairspoken for macOS (native)

Two native apps for macOS 26 on Apple Silicon, built from one XcodeGen project and a set of shared
Swift packages:

| App | Bundle id (Release / Debug) | What it is |
|---|---|---|
| **Fairspoken** (`Fairspoken.app`, scheme `MultiVoice`) | `ie.fairspoken.mac` / `.dev` | Menu-bar dictation: speech recognition on the Apple Neural Engine (FluidAudio + Parakeet CoreML), a Liquid Glass dashboard (Home, Models, Settings), a floating recording pill, and optional transcription on your own host |
| **Fairspoken Server** (`Fairspoken Server.app`, scheme `FairspokenServer`) | `ie.fairspoken.server` / `.dev` | A transcription server for a practice or a team: the host protocol of `src-tauri/src/host/PROTOCOL.md` on Parakeet and the Neural Engine, with a live view of who is dictating, models, configuration and the address clients need |

Fairspoken (Mac), the Windows and Linux desktop app and the web dashboard all talk to Fairspoken
Server exactly as they talk to the Rust `transcription-host`. The architecture follows
`swift-macos-app_plan.md` at the repo root.

## Build, test, run, install

```sh
cd apps/macos
brew install xcodegen                 # once
scripts/setup-signing.sh              # once per machine: a stable signing identity (see below)
scripts/build.sh                      # Debug, both apps → build/Build/Products/Debug/{Fairspoken,Fairspoken Server}.app
scripts/build.sh release              # Release, both apps
scripts/build.sh --app server         # one app: client | server | all
scripts/test.sh                       # unit tests: MultiVoiceCore (46) and FairspokenHost (41)
scripts/install.sh                    # Release Fairspoken → ~/Applications, then launches it
scripts/install.sh --app server       # the same for Fairspoken Server (--app all for both)
scripts/release.sh                    # Developer ID + notarized → build/release/Fairspoken-<version>-macos-arm64.{zip,dmg}
scripts/release.sh --app server       # → build/release/Fairspoken-Server-<version>-macos-arm64.{zip,dmg}
scripts/screenshots.sh                # docs/screenshots/ (client) and docs/screenshots/server-app/ (server)
open "build/Build/Products/Debug/Fairspoken Server.app"
```

`scripts/build.sh [release] [--app …] [SETTING=value ...]` passes extra build settings to xcodebuild
(`scripts/build.sh MV_SIGN_IDENTITY=-` builds ad-hoc, as CI does). `scripts/release.sh` is what the
release workflow runs, once per app; before its first local run, store the notarization credentials
with `xcrun notarytool store-credentials fairspoken-notary --apple-id <apple id> --team-id <TEAM_ID>`
(`--no-notarize` and `--unsigned` skip that). See `docs/releasing.md` at the repo root.

The `.xcodeproj` is generated by XcodeGen and git-ignored. Run `xcodegen generate` and open
`MultiVoice.xcodeproj` to work in Xcode (schemes `MultiVoice` and `FairspokenServer`).

## Fairspoken Server

### What it serves

- Every route of `PROTOCOL.md`: `GET /` (the web dashboard, `src-tauri/src/host/dashboard.html`
  bundled at build time, never copied), `/favicon.ico`, `/v1/health`, `/v1/stats`, `/v1/events`
  (SSE: snapshot first, `: ping` every 15 s, 16 subscribers, slow ones dropped at 256 frames),
  `POST /v1/config`, `/v1/models/download`, `/v1/transcriptions` (WAV) and
  `/v1/transcriptions/stream` (framed PCM16 over a chunked body).
- Bearer token on every route except `/` and `/favicon.ico`, `?token=` on GET only, compared in
  constant time. The `x-multivoice-*` headers, ids, event types, ordering rules, status codes and
  error strings are the Rust host's; `shared/host-conformance/` checks both hosts with the same suite.
- Behind `tailscale serve` (loopback), the client is the first `X-Forwarded-For` /
  `Tailscale-User-Login` value; those headers are trusted from loopback only.
- Models: **Parakeet TDT 0.6B v3** and **Parakeet Ultra**, on the Neural Engine. Each worker owns a
  decoder; workers on the same model share one copy of its weights (the FluidAudio spike measured 8
  concurrent decoders as correct, at ~2.1× the throughput of one). Parakeet Redux is not offered
  (its encoder runs mostly on the CPU on M4 + macOS 26). Models live in FluidAudio's shared cache,
  `~/Library/Application Support/FluidAudio/Models/`, which Fairspoken on the same Mac also uses.
- Streams are decoded while the client speaks: once 12 s are buffered, the audio is cut at the
  quietest 20 ms between 7 and 12 s and that segment decoded at once, so at release only the tail
  (≤ 12 s, 40–80 ms on the Neural Engine) is left. A streamed job's `processingMs` runs from the end
  of its upload, so it is the server's release-to-text, including any wait for a free worker.
- Vocabulary hints are accepted and not applied (the client restores its own casing); the
  `x-multivoice-language` header is accepted and ignored, as Parakeet detects the language.

Measured on the M4 (Release build, 100 ms frames sent in real time, 2 workers):

| | Fairspoken Server | Rust host (ONNX) |
|---|---|---|
| 4 s dictation, release → text | 72–91 ms | 133–136 ms on a quiet machine (820–1130 ms under load in one run) |
| 60 s dictation, release → text | 135–156 ms | 161–199 ms |
| 8 people releasing within 0.3 s, 4 s each | 111–151 ms each | not measured |
| Fairspoken (Mac) → server, `--selftest` | 114 ms (4× real-time upload) | |

The first launch of a new build compiles the encoder for the Neural Engine (13–25 s, once per model
path and macOS build); later launches load in under a second.

### Run modes

1. **App** (default): a menu-bar item (status, server address, copy token, start/stop, start at
   login) and a window: Activity (counters and the live constellation of clients → queue → workers →
   models), Clients, Models (download, delete, per-worker model), Connect (address, token, QR code)
   and Configuration. The toolbar's Live/Demo switch shows a simulated practice server instead of
   this one (the real server keeps serving). The window reads the host in-process: the same snapshot
   and event frames as `/v1/events`, decoded by the `HostEvent`/`HostLiveState` code in MultiVoiceCore.
2. **Start at login**: Configuration › This Mac › Start at login (`SMAppService.mainApp`). The app
   opens in the menu bar when you log in; System Settings › General › Login Items lists it.
3. **Headless**: `Fairspoken Server.app/Contents/MacOS/Fairspoken Server --headless` serves with no UI
   and logs one line per job (never transcript text) to standard output; SIGTERM / SIGINT stop it
   cleanly. As a per-user LaunchAgent (starts at login, restarted by launchd if it exits abnormally):

   ```sh
   scripts/server-agent.sh install [--app "/Applications/Fairspoken Server.app"] [--env KEY=VALUE ...]
   scripts/server-agent.sh status
   scripts/server-agent.sh uninstall
   ```

   Tested on this Mac: the agent served Neural Engine transcription (79 ms release → text) and launchd
   restarted it 1 s after a `kill -9`. Don't run the app at the same time (same port).

   **LaunchDaemon (no user logged in): not tested.** It should work with the same `--headless`
   command in `/Library/LaunchDaemons/` with a `UserName` key set to a normal account, so the server
   reads that account's FluidAudio model cache and config. Run as root it would look in
   `/var/root/Library/…` instead. Whether the Neural Engine is available before any login was not
   verified. Two caveats from the spike: keep `StandardOutPath` off external volumes (launchd exits
   78 when it can't open the log there), and expect the encoder compile on the first run per account.
4. **Keep awake**: while serving, the app and headless mode hold a `PreventUserIdleSystemSleep` power
   assertion (`pmset -g assertions` shows it), so the Mac doesn't idle-sleep; the display can still
   sleep. Configuration › This Mac › "Keep this Mac awake while serving" (`preventSleep`) turns it off.

### Configuration

`~/Library/Application Support/<bundle id>/host-config.json` (mode 0600; it holds the token). The
first four fields are the Rust host's file (`PersistedHostConfig`), so either host reads the other's:

```json
{
  "maxActiveStreams": 4, "maxRecordingSeconds": 600, "useGpu": true,
  "workerModels": ["parakeet-tdt-0.6b-v3", "parakeet-tdt-0.6b-v3", "parakeet-tdt-0.6b-v3", "parakeet-tdt-0.6b-v3"],
  "workerCount": 4, "queueCapacity": 8, "bindAddress": "127.0.0.1", "port": 48173,
  "token": "…", "preventSleep": true
}
```

- First launch writes defaults with a random 32-character token. An unreadable file stops the
  server (the window offers to reset it) rather than serving a configuration nobody chose.
- `maxActiveStreams`, `maxRecordingSeconds`, `useGpu` (here: Neural Engine on, CPU off) and
  `workerModels` change live, from the window or `POST /v1/config`, and are saved. Worker count,
  queue capacity, address, port and token restart the server when saved in the window.
- `bindAddress`: `127.0.0.1` (default, this Mac only; pair with `tailscale serve --bg 48173` to reach
  it on your tailnet over HTTPS), `0.0.0.0` (every network), or one address (e.g. the Tailscale IP).
- Environment variables (headless and testing; the same names as the Rust host):
  `MULTIVOICE_HOST_CONFIG_PATH`, and for this run `MULTIVOICE_HOST_ADDR`, `MULTIVOICE_HOST_TOKEN`,
  `MULTIVOICE_HOST_WORKERS`, `MULTIVOICE_HOST_QUEUE_CAPACITY`; `MULTIVOICE_HOST_MODEL`,
  `MULTIVOICE_HOST_MAX_ACTIVE_STREAMS`, `MULTIVOICE_HOST_MAX_RECORDING_SECONDS` and
  `MULTIVOICE_HOST_USE_GPU` only seed a first boot (the saved file wins afterwards, as in the Rust host).
  `--config <file>` points the app at another config file.

### Checking a host

```sh
# The Swift server headless on a test port, then the language-neutral suite (Node 22, no deps):
MULTIVOICE_HOST_ADDR=127.0.0.1:48981 MULTIVOICE_HOST_TOKEN=secret MULTIVOICE_HOST_WORKERS=1 \
MULTIVOICE_HOST_QUEUE_CAPACITY=2 MULTIVOICE_HOST_CONFIG_PATH=$(mktemp -d)/host-config.json \
  "build/Build/Products/Debug/Fairspoken Server.app/Contents/MacOS/Fairspoken Server" --headless &
node ../../shared/host-conformance/run.mjs --url http://127.0.0.1:48981 --token secret --slow
```

`Packages/FairspokenHost` also builds `fairspoken-host-dev` (`swift run fairspoken-host-dev`): the
real HTTP server, queue and workers over a stub engine, for protocol work without models.

## Fairspoken (dictation client)

Settings › Transcription › **My host** holds the host URL, token (Keychain) and timeout, a Test
connection button and a status line such as "Using host: practice-mini.local:48173 · connected"
(one `GET /v1/health` when Settings or Home opens, or on Test; no background polling). Monitoring a
host is Fairspoken Server's job (or the web dashboard at the host's `/`); the client has no Server view.

## Permissions you grant (once per signing identity + bundle id)

Fairspoken:

| Permission | Why | Where |
|---|---|---|
| Microphone | To record while the shortcut is active | System prompt (onboarding "Allow…") |
| Accessibility | To send ⌘V into the frontmost app and to detect secure/password fields. Without it, text is copied only | System Settings › Privacy & Security › Accessibility: switch on **Fairspoken** |
| Input Monitoring | Only for "hold fn to dictate" (a listen-only event tap) | System Settings › Privacy & Security › Input Monitoring |

Onboarding shows live status for each permission and deep-links to the right pane. For hold-fn, also set
System Settings › Keyboard › "Press 🌐 key to" › **Do Nothing**. If the Tauri app is running, quit it or
change one app's shortcut, because both default to ⌘⇧1.

Fairspoken Server needs no privacy permission to serve loopback. Listening on `0.0.0.0` or a LAN
address may bring up macOS's Local Network prompt the first time another device connects; allow it.

**Signing and TCC:**
- macOS keys these grants on the bundle id *and* the code signature's designated requirement.
- Ad-hoc builds change signature on every build, which silently revokes Accessibility.
- `scripts/setup-signing.sh` writes `Config/Local.xcconfig` (git-ignored). It uses an Apple Development or
  Developer ID identity if one is installed, and otherwise creates a self-signed "Fairspoken Local Signing"
  certificate that you trust once in Keychain Access.
- Debug and Release use different bundle ids, so each needs its own grants and they never clobber each other.
- **Changing the bundle id or signing identity later resets every user's grants.**

## Naming and identifiers

- **Display names:** `MV_DISPLAY_NAME` in `Config/Base.xcconfig` (Fairspoken) and `Config/Server.xcconfig`
  (Fairspoken Server). They flow into `CFBundleDisplayName` and the .app names; Swift reads them back
  (`AppInfo.displayName`, `ServerInfo.displayName`). Release files are `<client name>-…` and
  `<client name>-Server-…`.
- **Bundle ids:** `MV_BUNDLE_ID_BASE` in the same files; Debug appends `.dev` (`Config/Debug.xcconfig`).
  `Config/Server-{Debug,Release}.xcconfig` include the client's and then `Server.xcconfig`, so version,
  signing and Swift settings are shared.
- **Brand:** `FairspokenUI` holds the palette (`Color.fs*` from `design/brand/README.md`: Copybook Blue,
  Margin Red for the signal only, Limestone/Night, status colours) and the mark (`FairspokenMark`, the
  logo's own paths). The server follows the brand's Liquid Glass rules: glass only on the control layer
  (sidebar, toolbar, constellation nodes); cards, tables and charts are opaque. The client keeps its
  teal look (`Brand`, `BrandMark`) until it is re-skinned. The server icon is the brand's dark icon
  composite (`scripts/make-server-icon.sh`); no taglines anywhere.
- **Internal names keep "MultiVoice":** the `MultiVoiceCore` package, the `MultiVoice` target and scheme.
  Wire identifiers are unchanged per `PROTOCOL.md`: the `x-multivoice-*` headers, the
  `application/vnd.multivoice.pcm-stream` content type, `MULTIVOICE_HOST_*` and the client id `multivoice-macos`.

## Layout

```
project.yml                      XcodeGen spec: two app targets, KeyboardShortcuts 1.10.0, local packages
Config/                          Base/Debug/Release (client), Server*.xcconfig, entitlements
MultiVoice/                      Fairspoken
  Sources/App/                   main, AppDelegate, AppModel (composition root), windows, status item, screenshots, self-test
  Sources/Audio/                 AVAudioEngine capture → 16 kHz mono Float32, device selection, level meter
  Sources/Engine/                ModelLibrary, local/remote sessions, HostStatus ("My host" reachability)
  Sources/Dictation/             DictationController state machine
  Sources/System/                Permissions, TextInserter (⌘V + clipboard restore), hotkeys + Fn tap, sounds
  Sources/Storage/               settings.json / transcript-history.json / usage-stats.json (Rust schemas), Keychain
  Sources/UI/                    Home, Models, Settings, Onboarding, Pill
FairspokenServer/                Fairspoken Server
  Sources/App/                   main (app or --headless), delegate + menu bar, headless runner, login item, sleep guard, screenshots
  Sources/Engine/                FluidAudioBackend (the host's speech engine)
  Sources/Model/                 ServerController (host lifecycle, live state, demo, config), network addresses
  Sources/UI/                    window, Activity + constellation (HostGraphView, FlowAnimator), Clients, Models, Connect, Configuration
Packages/
  MultiVoiceCore/                platform-neutral core + tests: frame codec, URL policy, protocol types, SSE parser,
                                 host events/stats/live-state reducer, polling differ, simulator, settings/history models
  FairspokenSpeech/              the only FluidAudio code (pinned 0.17.5): model registry, the client's engine,
                                 the server's worker pool (shared weights, one decoder per worker)
  FairspokenHost/                the server runtime + tests: HTTP/1.1 on Network.framework, routing and auth, queue,
                                 workers, metrics, SSE fan-out, config file; `fairspoken-host-dev` (stub engine)
  FairspokenUI/                  shared SwiftUI: palette, cards, chips, tags, brand mark, formatting
scripts/                         build, test, install, release, screenshots, setup-signing, server-agent, make-*-icon
```

**Why Network.framework rather than Hummingbird / SwiftNIO:** the host needs exact control of the wire
(SSE flushed per frame as one chunk, close-delimited bodies for HTTP/1.0, the response to an early 4xx
while a stream is still uploading, `Expect: 100-continue`), a streaming request-body reader for the frame
protocol, and binding to one interface address. Network.framework does all of that with no dependency
tree (SwiftNIO, swift-log, swift-metrics, swift-collections…); the HTTP/1.1 codec is ~400 lines, pure,
and unit-tested on its own, and the server is tested end to end over in-memory pipes and real sockets.

Client data lives in `~/Library/Application Support/<bundle id>/`. On first launch the client imports
`~/.config/multivoice-tauri/{settings,transcript-history,usage-stats}.json` once. Secrets move to the
Keychain, and the JSON keeps empty strings. Keys the app doesn't model are preserved on save.
